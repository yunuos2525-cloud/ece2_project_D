# FPGA W2 x STM32 SPI cross-integration report

Date: 2026-11-15 (Asia/Seoul)

## Scope and source

- Common specification: `docs/TEAM_SPI_INTERFACE_v8_final.md`
- STM32 source commit: `91a1a077fabd8a4c83a0ea8f5b9237c45b87b70b`
- STM32 serializer/deserializer: `STM32/src/fpga_link.c` from that commit
- STM32 coefficient generator: `STM32/src/audio_dsp.c` from that commit
- FPGA implementation: local W2 `spi_mode0_slave_w2.sv`, `analysis_buffer_512.sv`, and `iir_notch_variable.sv`
- Confirmed physical integration target: `NUCLEO-G474RE`
- Execution type: PC host execution with virtual SPI callbacks. This is not a physical STM32 SPI capture.

The test script exports the named STM32 Git blobs into a temporary directory, compiles them without source edits, and calls the real `fpga_set_mode`, `fpga_read_state`, `fpga_read_block`, and `fpga_set_coeff` functions. The captured TX bytes are written to `stm32_frames.hex` and replayed by the FPGA cross testbench.

Final classification: **PASS for simulated SPI protocol and FPGA RTL compatibility**.

## Timing represented by the testbench

- SPI Mode 0: MOSI set during SCK Low, FPGA/host sample on the rising edge, MISO changes after falling edges.
- MSB first.
- SCK period: 2 us, nominal 500 kHz.
- READ_BLOCK preserves CS Low across both C transfer calls.
- A deliberate 10 us SCK-stopped interval is inserted between the two READ_BLOCK transfers.
- The SET_COEFF result is applied only at a subsequent FPGA sample-valid edge.

## Problems found

The first testbench run waited for `coeff_update_valid` after its one-clock pulse had already completed and timed out. Classification: **testbench problem**, not STM32 or FPGA protocol failure. The cross-only TB was changed to count the pulse and independently verify sample-edge application. The final run shown in the evidence passed.

No common-spec violation, serializer mismatch, CRC mismatch, byte-position mismatch, or Mode-0 edge mismatch was found in the tested paths. Therefore no change to the existing FPGA RTL or STM32 C implementation is required from this simulation result.

## Not verified by this result

- Physical STM32 GPIO/SPI waveforms, clock accuracy, HAL timing, and actual board firmware image
- FPGA/STM32 voltage levels, common ground, J10/BD_SEL1 direction, MISO contention, and connector wiring
- Execution on the confirmed physical `NUCLEO-G474RE` and verification of its actual GPIO waveforms
- Bitstream behavior on the physical FPGA board

Those items require a logic-analyzer and board-level integration test. This report must not be represented as a physical-board POST result.
