# FPGA–STM32 공통 통신·데이터 규격 · v8

> **공통 구현 규격.** 양방향 SPI·가변 Notch의 실제 보드 동작은 검증 대상이며, 핀 연결이나 메시지 형식 변경 시 양측 소스와 규격을 함께 수정한다.
> 핵심 기능: STM32의 미지 단일 간섭 주파수 추정·계수 계산 + FPGA의 실시간 가변 Notch 처리.

## 1. 전체 역할과 신호 흐름

```text
                    [실시간 오디오 경로 — FPGA에서 계속 동작]
함수발생기 ──> ADC ──> FPGA [BYPASS/FIXED/AUTO Notch] ──> DAC ──> 오실로스코프
                       │                           ▲
                       │ 512샘플 블록 (MISO)       │ 필터 계수·모드 명령 (MOSI)
                       ▼                           │
                   STM32 [FFT로 주파수 추정 + IIR 계수 계산]
```

- FPGA는 **16,000 samples/s, unsigned 8-bit, mono**를 실시간 처리한다.
- STM32는 FFT용 **512개 샘플 블록**을 읽고, 700~3,000 Hz(초기 제안 범위)에서 미지의 간섭 **1개**를 추정한다.
- STM32가 2차 IIR Notch의 계수 5개를 계산하여 FPGA에 보낸다. FPGA가 모든 샘플의 실제 필터 연산을 수행한다.
- **오디오 경로와 STM32 분석/설정 경로는 비동기적**이다. 새 계수가 도착할 때까지 오디오 경로가 멈추지 않는다.
- FPGA의 스위치는 **Text LCD 표시 모드(신호처리/시계/스톱워치)**를 선택한다. STM32가 전송하는 **DSP 동작 모드(BYPASS/FIXED/AUTO)**와 별개다.

## 2. SPI 전기·역할·타이밍

| 항목 | 규격·확인 상태 |
|---|---|
| Master / Slave | **STM32 / FPGA**, 역할 고정 |
| Mode / 비트 순서 | **SPI Mode 0** (CPOL=0, CPHA=0), **MSB first** |
| MOSI | STM32 → FPGA: 모드 명령, 계수, 읽기 명령 |
| MISO | FPGA → STM32: 분석용 샘플, 통신 상태 응답 (**신규 구현·검증 필요**) |
| SCK / MOSI / CS | STM32 PB3 → FPGA F8, STM32 PA7 → FPGA E8, STM32 PB6 → FPGA A7 (GPIO 대체기능·배선 확인) |
| MISO 핀 | **STM32 PA6(SPI1_MISO, CN5 D12/5번 또는 CN10 13번) ↔ FPGA BDIO03(패키지 G8)**. 핀 배정 확정; 보드 J10 접속 위치·BD_SEL1 선택 상태·전압·출력 충돌은 실물 시험 확인 |
| 초기 SPI 클록 | **500 kHz 이하부터 점검**(설계 시작값). 전송 안정성 확인 후 조정. FPGA의 50 MHz 동기화 로직에서 실제 설정으로 검증 |
| 프레임 | **CS low 1회 = 명령 1개 + 그 명령에 필요한 데이터**. CS high에서 프레임 종료. **STM32만 SCK 생성** |
| 전원 재시작 상태 | FPGA: BYPASS, 자동 계수 없음. 연결 재시도 후 STM32가 다시 초기 설정 전송 |
| 전기 안전 | 공통 GND, 3.3 V 신호 호환, 핀 방향·다른 주변회로와 충돌 여부 확인 후 배선 |

**검증 기준:** MISO는 FPGA가 출력하고 STM32가 입력한다. SCK/MOSI/CS 동작과 별개로 MISO 송수신을 실물에서 시험한다.


### MISO 핀·배선 확인 절차

1. **STM32 측:** NUCLEO-H533RE의 **CN5 D12(5번 핀) = PA6 = SPI1_MISO**를 사용한다. 동일 신호는 **CN10 13번 핀**으로도 접근할 수 있다. STM32 핀 설정에서 **PA6가 SPI1_MISO로 할당**되었는지 확인한다.
2. **FPGA 측:** 실습 장비 교재 핀 구성표에서 **BDIO03 = FPGA 패키지 G8** 확인. 회로도상 BDIO03은 U19 버스 스위치를 통해 **J10**으로 연결된다. 실제 점퍼선 위치 및 `BD_SEL1` 선택 상태는 현장에서 확인한다. `G8`은 보드 점퍼선 위치가 아니라 FPGA 칩의 패키지 핀 번호다.
3. **전기 확인:** 보드 전원을 끄고 공통 GND·연결 위치·다른 회로와 충돌 여부를 확인한다. 양측 전압이 3.3 V 호환인지 확인한 뒤 연결한다.
4. **단순 통신 시험:** FPGA가 알려진 1바이트 패턴(`0xA5`, `0x5A`)을 MISO로 응답하게 하고 STM32가 읽는지 확인한다. 이후 16바이트, 512바이트와 CRC로 확대한다.
5. **성공 판정:** STM32가 받은 값이 FPGA가 보낸 값과 동일하고, 반복 전송에서도 비트 순서·샘플 누락·배선 충돌이 없어야 한다.

**핀 근거:** STMicroelectronics, *UM3121 STM32H5 Nucleo-64 board (MB1814)*, ARDUINO 커넥터 표 16(27쪽), ST morpho 커넥터 표 17(29쪽). FPGA 측은 수업 실습 장비 교재 「CH2. FPGA 디지털 로직 설계」의 BDIO 핀 구성표(BDIO03=G8) 및 회로도를 기준으로 한다.

## 3. 공통 명령 목록

| 명령 1바이트 | 이름 | 이후 바이트/동작 | 우선순위 |
|---|---|---|---|
| `0x01` | `BYPASS` | 추가 바이트 없음. ADC 원본 경로 선택 | 필수 |
| `0x02` | `FIXED` | 추가 바이트 없음. 미리 설정된 **1,000 Hz** Notch 선택 | 필수 |
| `0x06` | `AUTO` | 추가 바이트 없음. STM32가 전송한 마지막 유효 가변 계수 사용 | 필수 |
| `0x10` | `READ_BLOCK` | MISO로 512샘플 + 메타데이터 응답 | 필수·신규 |
| `0x20` | `SET_COEFF` | MOSI로 필터 계수 5개 전송 | 필수·신규 |
| `0x21` | `READ_STATE` | MISO로 현재 모드·적용한 계수 번호 확인 | 필수 확인용·신규 |
| `0x05` | `CLEAR_ERROR` | 샘플 누락 등의 sticky 진단 플래그만 초기화(구현 시) | 선택·예약 유지 |
| `0x03`, `0x04` | 예약 | 미사용 | 미사용 |

**미지원 명령·불완전 프레임:** 이전 정상 DSP 모드와 계수를 보존한다. 단순 SPI 송신 완료를 **필터 적용 성공**으로 기록하지 않는다.

## 4. `READ_BLOCK` — FPGA 샘플을 STM32로 읽기

분석 블록은 512개이고 **512 / 16,000 = 32 ms**의 입력을 대표한다. FPGA는 샘플을 순서대로 채운 뒤 블록을 고정하여 STM32가 읽는 동안 값이 바뀌지 않게 한다(이중 버퍼 등 구현 방식은 FPGA 담당자 결정).

| 순서 | MOSI (STM32가 전송) | MISO (STM32가 읽음) |
|---|---|---|
| 1바이트 | `0x10` | 무시 |
| 2바이트 | Dummy `0x00` | `status` |
| 3바이트 | Dummy `0x00` | `block_id_lo` |
| 4바이트 | Dummy `0x00` | `block_id_hi` |
| 다음 512바이트 | Dummy `0x00` 반복 | `sample[0]` ... `sample[511]` |
| 마지막 1바이트 | Dummy `0x00` | `crc8` |

- `status` bit0: 새 블록 있음(1) / 없음(0). bit1: 버퍼 과부하로 샘플 블록 손실 발생 기록(1). 나머지 비트는 0으로 예약.
- `status.bit0=0`이면 STM32는 **그 자리에서 CS high로 종료**하고 샘플·CRC를 읽지 않는다.
- `block_id`는 16-bit unsigned, **little-endian**, 블록 생성마다 1 증가(65535 이후 순환). STM32는 이 값으로 **중복·건너뛴 블록**을 감지한다.
- `sample[n]`은 offset-binary unsigned 8-bit이며, STM32는 FFT 전에 중심값(대략 128)을 빼고 필요하면 DC 평균을 제거한다.
- `crc8`은 `[block_id_lo, block_id_hi, sample[0..511]]`에 대한 CRC-8/ATM (다항식 `0x07`, 초기 `0x00`, xorout `0x00`, 비반사)이다.
- **512샘플과 CRC까지 끝까지 전송하고 CS high로 종료한 경우에만** FPGA가 해당 블록을 읽기 완료로 처리한다. 중도 종료 시 블록 재요청을 허용한다.
- STM32가 읽는 동안 FPGA는 다음 입력을 계속 수집한다. 가용 블록이 없으면 버퍼를 덮어써서 멀쩡한 블록을 위조하지 말고, 실제 손실을 플래그/블록 번호로 드러낸다.

**대역폭 감각:** 원시 데이터만 **16,000 byte/s = 128 kbit/s**. 512샘플 읽기 1회는 약 517바이트(프레임 포함)이므로 500 kHz SPI에서 순수 클록 구간은 약 **8.3 ms**, 1 MHz에서는 약 **4.1 ms**다. 실제 MCU 처리·CS 간격까지 포함한 기한을 W2 실측으로 확인해야 하며, 이 수치만으로 실시간성을 증명할 수는 없다.

## 5. `SET_COEFF` — STM32가 가변 Notch 계수 전송

### 차분방정식 및 데이터 표현

FPGA가 구현하는 식은 아래와 같이 **부호를 고정**한다.

\[
y[n] = b_0x[n] + b_1x[n-1] + b_2x[n-2] - a_1y[n-1] - a_2y[n-2]
\]

- 계수 순서: **`b0, b1, b2, a1, a2`**.
- 각 계수는 **signed 16-bit Q2.14**(실수 값 × `2^14` 반올림), **little-endian** 전송. 표현 범위 약 `[-2.0, 1.99994]`.
- `a1` 자체는 식의 `-a1·y[n-1]`에 들어가는 **부호 있는 값**이므로, MCU/FPGA가 음수를 이중 적용하지 않도록 테스트할 것.
- 계수 계산 모델의 시작 예시는 `ω0=2π f_est /16000`, `b0=1`, `b1=-2cosω0`, `b2=1`, `a1=-2r cosω0`, `a2=r²`, `0<r<1`이다. `r`과 이득 보정은 공동 시뮬레이션에서 정하고 기록한다. 이 예시는 보드에서 검증된 최종 계수가 아니다.

### 전송 프레임

```text
MOSI: [0x20] [seq 1B] [b0 lo][b0 hi] [b1 lo][b1 hi] [b2 lo][b2 hi]
      [a1 lo][a1 hi] [a2 lo][a2 hi] [crc8 1B]
```

- 전체 **13바이트**. `crc8` 범위는 `[seq, b0_lo, b0_hi, ..., a2_hi]`의 **11바이트**. 방식은 위와 동일한 CRC-8/ATM.
- FPGA는 **13바이트 완성 + 정상 CRC**를 만족한 프레임만 받아들인다. 임시 버퍼에 모아 둔 뒤 **다음 샘플 처리 경계에서 계수 5개를 동시에 교체**한다.
- `seq`는 STM32가 새 계수 세트마다 1 증가시키는 8-bit 번호(0~255 순환). STM32는 `READ_STATE`로 해당 번호가 실제 적용됐는지 확인할 수 있다.
- 계수 전송 실패·전원 중단·일부 바이트 누락 시에는 **기존 유효 계수 유지**, 오디오 경로 중단 금지.
- 계수 변경 순간의 출력 튐/필터 내부 지연 상태는 별도로 실험한다. **원자적 교체는 계수 혼합을 막지만 출력 튐을 저절로 없애 주지는 않는다.**

## 6. `READ_STATE` — 실제 적용 여부 확인

| 순서 | MOSI | MISO |
|---|---|---|
| 첫 1바이트 | `0x21` | 무시 |
| 다음 1바이트 | Dummy | `active_mode` (`0x01`/`0x02`/`0x06`) |
| 다음 1바이트 | Dummy | `applied_coeff_seq` (유효한 AUTO 계수 없으면 `0xFF`) |
| 다음 1바이트 | Dummy | `flags` (bit0: AUTO 계수 유효, bit1: 블록 손실 기록) |

- STM32가 `SET_COEFF`를 보내고 `READ_STATE`에서 `applied_coeff_seq`가 일치하면 **FPGA가 계수를 적용했다는 디지털 확인**을 얻는다.
- 이것은 **실제 아날로그 출력에서 간섭이 줄었다는 증거는 아니다**. 감쇠 성능은 오실로스코프/파형 분석으로 검증한다.

## 7. 시작·변경·오류 시퀀스

1. **초기화:** FPGA BYPASS. STM32 초기 상태에서 샘플 읽기·FFT/계수 계산을 준비한다.
2. **FIXED 검증:** STM32 `0x02` 전송 → FPGA 1 kHz Notch 출력 → 오실로스코프 확인.
3. **AUTO 시작:** STM32 `READ_BLOCK` → FFT로 간섭 추정 → `SET_COEFF` → `READ_STATE`로 계수 적용 확인 → `0x06` AUTO. 유효 계수가 없으면 FPGA는 임시 BYPASS.
4. **주파수 변경:** 다음 샘플 블록들을 분석해 유효한 새 간섭으로 판단되면 새로운 `seq`와 계수를 전송. FPGA는 **기존 필터로 계속 처리하다가** 새 계수 적용 경계에서 변경.
5. **정상 간섭이 없을 때:** STM32는 근거 없이 임의의 피크를 간섭으로 선택하지 않는다. 처리 정책은 최초 자동 모드에서 BYPASS, 이미 안정적으로 필터링 중이라면 직전 설정 유지 후 재확인하는 것으로 시작하고 W2 테스트로 검증한다.
6. **통신 이상:** 누락된 블록·CRC 오류·읽기 중단 시 재시도/다음 블록으로 복구. FPGA 오디오 자체는 계속 출력. `CLEAR_ERROR`는 오류 검출과 무관한 **선택적 기록 초기화**일 뿐이다.

## 8. 구현 전 반드시 공동 확인할 사항

- **하드웨어 1순위:** FPGA BDIO03/G8의 실제 J10 접속 위치·버스 스위치 활성화, STM32 PA6의 SPI1_MISO 설정, 공통 GND·전압, 스위치/점퍼·기타 기능 충돌.
- **기본 시험:** 송수신 모두 1바이트 패턴 → 16바이트 → 512바이트 + CRC 순서로 검증. 처음부터 FFT/가변 Notch와 한꺼번에 결합하지 않는다.
- **수치 시험:** 두 보드가 **정확히 같은 계수 순서·부호·Q2.14**를 해석하는지 1 kHz 기준 계수로 비교.
- **속도 시험:** 32 ms마다 생성되는 블록을 STM32가 처리하고 다음 블록을 읽을 수 있는지 실제로 확인. 실패 시 버퍼 정책·FFT 프레임·SPI 속도를 조정한다.
- **대체 경로(미확정):** 보드에서 MISO 경로 확보가 불가능하면, 팀이 합의한 뒤 STM32 ADC로 동일 아날로그 입력을 따로 샘플링하는 대안을 검토할 수 있다. **이번 v8의 기본 설계는 아니며**, 그 경우 인터페이스 문서 자체를 개정해야 한다.

## 9. 인터페이스 검증·변경 관리

- **검증 대상:** MISO 송신/수신, 512샘플 블록의 완전성, 계수 전송·적용, AUTO 동작, 재시작 복구.
- **공통 필수 준수:** 명령 코드·패킷 길이·CRC·바이트 순서·Q2.14 부호를 일치시킨다.
- 규격 변경 시 팀 인터페이스 문서와 양쪽 소스 및 테스트 데이터를 함께 갱신한다.
